# 特权级别

## 概述

特权级别（Privilege Levels）是操作系统实现隔离与保护的基础。RISC-V 特权架构定义了多个运行级别，用于区分“受限的用户代码”和“拥有硬件控制权的内核代码”。

在本教程中，我们主要关注三种模式：

- **U-mode（User）**：用户态，权限最低
- **S-mode（Supervisor）**：监管态（许多 OS 在这里运行内核）
- **M-mode（Machine）**：机器态，权限最高（裸机/固件/最小内核常用）

本仓库为了简化，主要在 **M-mode** 下运行内核，并演示切换到 **U-mode** 的流程骨架（见 `src/kernel/usermode.rs`）。

## 为什么需要特权级

没有特权级，用户程序可以随意：

- 读写任意内存（包括内核数据结构）
- 操作 MMIO 外设
- 关闭中断或改写异常入口

这会让系统几乎不可用。特权级让内核能：

- 限制用户态能做的事
- 提供受控入口（系统调用）让用户态“请求服务”
- 遇到违规访问时通过异常机制接管并处理

## mstatus.MPP：异常返回时“回到哪个级别”

在 RISC-V 上，进入 trap 后 CPU 会切到更高特权级执行 handler，并记录“之前的特权级”信息。

对机器模式而言，`mstatus` 的 `MPP` 位域表示：

- trap 发生前的特权级
- 执行 `mret` 返回时会恢复到 `MPP` 指示的级别

因此切换到用户态常见步骤之一就是：

1. 设置 `mstatus.MPP = U`
2. 设置 `mepc = user_entry`
3. 执行 `mret`

本仓库在 `src/arch/riscv.rs` 提供了 `write_mpp()`，并在 `src/kernel/usermode.rs` 中演示了这一步（但还未实现 `mret` 返回路径）。

## 小结

本章你应该理解：

- 特权级是隔离与保护的基础
- RISC-V 有 U/S/M 多种模式，本项目以内核跑在 M-mode 为主
- `mstatus.MPP` 决定 `mret` 返回到哪个特权级，是实现用户态切换的关键
