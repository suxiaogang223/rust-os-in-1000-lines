# FAT文件系统

## 概述

FAT（File Allocation Table）是一类非常经典、结构清晰的文件系统，常见于：

- U 盘/小容量存储介质
- 各类引导分区/嵌入式设备

它的优势是：

- 格式简单，适合教学
- 目录项与 FAT 表结构直观
- 易于实现一个“能列目录/能读文件”的最小版本

本仓库在 `src/fs/fat.rs` 提供了一个教学版 FAT 文件系统骨架，演示了：

- 读取并校验引导扇区签名（`0xAA55`）
- 解析部分 BPB 参数（总扇区数、每簇扇区数、FAT 区大小等）
- 构造一个简化的 FAT 表与根目录（当前为示例数据）

## FAT 的核心结构

你可以把 FAT 卷想象成这样几块区域：

1. **Boot Sector（引导扇区）**：包含 BPB（BIOS Parameter Block）与签名
2. **FAT 表（可能有多份）**：记录簇链（cluster chain）
3. **Root Directory（FAT12/16 固定区域；FAT32 更灵活）**：目录项数组
4. **Data Area**：真正存放文件数据的簇区域

本仓库为了教学，把很多细节做了简化，但整体结构与真实 FAT 的分区方式保持一致的思路。

## 引导扇区与签名

FAT 引导扇区末尾常见有签名 `0xAA55`（位于偏移 510/511）。

本仓库在 `parse_boot_sector()` 中做了校验：

- 读取 `boot_sector[510..512]`
- 解析成小端 `u16`
- 与 `0xAA55` 比较

如果签名不对，则认为卷格式不正确。

## BPB 参数：卷的“元信息”

真实 FAT 的 BPB 字段非常多，这里只关注本仓库解析的几个：

- `total_sectors`：总扇区数
- `sectors_per_cluster`：每簇扇区数
- `fat_sectors`：FAT 区占用扇区数
- `root_dir_sectors`：根目录区占用扇区数（由根目录项数推导）
- `data_sectors`：数据区扇区数（由总量减去其他区域得到）

这些参数决定了：

- 从哪开始读 FAT
- 从哪开始读目录
- 数据区的簇编号如何换算到 LBA 扇区号

## 当前实现的简化点

`src/fs/fat.rs` 目前的重点是教学框架，因此做了不少简化：

- FAT 表 `load_fat_table()` 里没有真实读取磁盘数据，而是把条目填成 `0xFFFF`
- 根目录 `load_root_directory()` 直接构造了两个示例条目（一个文件，一个目录）
- 读取文件 `read_file()` 不走簇链，不从磁盘读数据，而是填充演示数据

这样做的好处是：先把 API 与数据结构串起来，让你能在串口上看到“列目录/打开文件/读取”这一条链路。

## 小结

本章你应该理解：

- FAT 卷的区域划分：Boot/FAT/Root/Data
- 引导扇区签名与 BPB 参数的作用
- 本项目当前以“跑通结构”为主，后续可逐步替换为真实的 FAT 表读取与簇链遍历
