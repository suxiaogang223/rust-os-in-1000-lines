# 用户交互

## 概述

用户交互（User Interaction）解决的是：如何从串口读取用户输入、如何回显、如何处理退格/方向键等编辑行为。

本仓库目前的 Shell 为了演示结构，把输入读取简化为固定字符串（`read_input()` 直接返回 `"help"`）。这让我们能先把命令分发与子系统调用跑通。

当你希望 Shell 真正可用时，需要把输入部分接到 UART 驱动的接收能力上（见 `src/drivers/uart.rs:get_char/has_data`）。

## 串口输入的最小实现（轮询）

最小实现通常是一个循环：

1. 等待 UART 有数据（`LSR_DR`）
2. 读一个字符
3. 处理特殊字符（`\r/\n` 结束、`\x08` 退格等）
4. 存入缓冲区并回显

在 `no_std` 场景下，缓冲区可以用固定数组：

```text
let mut buf = [0u8; 128];
let mut len = 0;
```

当用户按回车时，把 `buf[..len]` 解析成 `&str`（需要 UTF-8 校验或限制输入为 ASCII）。

## 回显与行编辑

为了让交互体验更接近正常终端，需要支持：

- 回显：用户输入什么，屏幕显示什么
- 退格：删除最后一个字符并更新显示

早期内核可以只做非常基本的处理：

- 退格时输出 `\x08 \x08`（光标左移、擦除、再左移）

## 与中断驱动输入的关系

轮询输入实现简单，但会忙等，占用 CPU。

当你实现中断与外部中断控制器后，可以改成：

- UART 收到数据触发中断
- 中断 handler 把字符放入 ring buffer
- Shell 从缓冲区读取，不需要忙等

这会把系统从“教学演示”推进到“更像真实 OS”的交互模型。

## 小结

本章你应该理解：

- 可用的 Shell 需要真正的串口输入读写与回显
- 轮询输入最简单但会忙等；中断驱动输入更高效
- 本仓库目前用固定输入占位，后续可按本章思路逐步补齐
