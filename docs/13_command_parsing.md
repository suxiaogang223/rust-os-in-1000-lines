# 命令解析

## 概述

命令解析（Command Parsing）把用户输入的字符串转换为结构化的命令，例如：

```
create 4096
```

解析结果可能是：

- 命令名：`create`
- 参数：`4096`

本仓库目前的解析是最简版：`match input.trim()` 直接匹配固定命令（见 `src/user/shell.rs:Command::parse`）。本节解释这种做法的意义，并给出如何演进到“带参数/带路径”的解析器。

## 当前实现：固定命令匹配

当前 `Command::parse()`：

- 去掉首尾空白
- 与 `"help"/"list"/"create"/"exit"` 做字符串匹配
- 其他输入统一归为 `Unknown`

这种做法的优点：

- 实现极简单，便于把 Shell 跑起来
- 不依赖分词器/动态分配

缺点：

- 不支持参数
- 不支持路径
- 不能做更丰富的错误提示

## 演进方向 1：空格分词 + 参数数组

最常见的第一步是：

1. 按空格拆分成 token
2. 第一个 token 是命令名，其余是参数

然后把命令表达为：

```text
Command::Create { stack_size: usize }
Command::Cat { path: String }
...
```

在 `no_std` 环境下，如果你想避免堆分配，可以使用：

- 固定大小的 token 缓冲区
- 在原地切分（记录起止索引）

## 演进方向 2：错误处理与帮助系统

解析器不仅要“解析成功”，也要能“解释失败”：

- 未知命令：提示 `help`
- 参数缺失：提示用法
- 参数格式错误：提示应为数字/路径等

这会大幅提升 Shell 的可用性，也能帮助你更快验证内核功能。

## 小结

本章你应该理解：

- 命令解析是 Shell 的“前端”，把字符串转成结构化命令
- 教学阶段可以用固定匹配跑通链路
- 更可用的 Shell 需要分词、参数解析与错误提示机制
