# 堆管理

## 概述

分配器解决“怎么分配”的问题；堆管理解决“从哪里分配”的问题。

在一个真正的内核里，堆通常来源于：

- RAM 中的一段可用区域
- 由引导加载器/设备树提供的内存地图
- 内核镜像之后的空闲内存（由链接脚本导出符号）

本仓库为了把重点放在机制上，直接在 `kernel::init()` 里指定了一段固定内存作为堆（见 `src/kernel/mod.rs`）。

## 本项目的堆区设定

当前初始化写死为：

- 起始：`0x2000_0000`
- 大小：`1 MiB`

对应代码：

```rust
memory::init_memory(0x2000_0000, 1024 * 1024);
```

### 这有什么问题？

在真实机器上，你不能随便假设某段地址一定是 RAM 且可用；否则可能覆盖：

- MMIO 外设寄存器
- 只读区域
- 内核镜像本身

因此当你把项目推进到“更真实”的阶段时，建议把堆区来源改为：

- `linker.ld` 导出的 `_end` 符号（内核镜像末尾）
- 设备树/bootloader 提供的 RAM 范围

## 堆的生命周期：什么时候初始化

一般来说：

1. **串口先初始化**：保证能打印调试信息
2. **异常处理/最小 trap 框架**：防止早期错误无声崩溃
3. **堆初始化**：让后续数据结构能动态分配

本仓库的 `kernel::init()` 也是按这个顺序组织的。

## 未来扩展：从堆到页分配

当你实现分页（第 08 章）并开始管理大量内存时，常见做法是：

- 把物理内存按页（4KiB）划分
- 实现页分配器：`alloc_page()/free_page()`
- 在页分配器之上实现更灵活的堆分配器（slab、buddy、jemalloc-like 等）

这样能更好地支持：

- 页表分配与回收
- 进程地址空间管理
- 文件系统缓存等

## 小结

本章你应该理解：

- 堆管理关注“可用内存从哪来、边界在哪”
- 本项目用固定地址简化了堆区来源
- 真实内核通常会逐步演进为“页分配器 + 堆分配器”的组合
