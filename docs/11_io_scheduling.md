# I/O调度

## 概述

I/O 调度（IO Scheduling）解决的是：当系统同时有很多读写请求时，如何安排这些请求的执行顺序，以达到更好的吞吐、延迟和公平性。

在现代系统里，I/O 调度可能发生在多个层次：

- 文件系统层：合并写、预读、延迟分配
- 块层：请求队列、调度算法（deadline、CFQ、BFQ 等）
- 设备层：NCQ、多队列、硬件内部调度

本教程的目标是把“块设备 + 文件系统”跑通，因此本仓库目前没有实现完整的 I/O 调度器，而是以同步/简化方式演示接口。

## 为什么仍然要了解 I/O 调度

即使你暂时不实现调度器，理解它也有助于你设计接口：

- 是否需要异步提交请求？
- 是否需要队列与回调/中断完成通知？
- 是否需要合并相邻请求？

这些决定会影响磁盘驱动与文件系统之间的边界。

## 最小学习版的“调度”可以怎么做

如果你想在本项目里加一个最小 I/O 调度器，可以从非常简单的策略开始：

- 用一个队列保存 pending 请求
- 一次只处理一个请求（FIFO）
- 完成后唤醒等待者（或轮询检查）

当你实现了真正的 virtio-blk 并引入中断完成通知后，这个队列就会变得更有意义。

## 小结

本章你应该理解：

- I/O 调度的目标是平衡吞吐、延迟与公平
- 教学内核可以先用同步方式跑通数据路径
- 当引入异步驱动与中断后，I/O 请求队列与调度策略才会成为“必须品”
