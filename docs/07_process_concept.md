# 进程概念

## 概述

当内核从“只打印 Hello”走向“同时跑多个任务”时，就需要引入进程/线程的概念。

在学习型内核里，我们可以先用非常简化的模型理解三件事：

1. **进程是什么**：一段可执行代码 + 运行时状态
2. **进程需要保存哪些状态**：寄存器、栈、程序计数器、以及资源引用
3. **内核如何管理一组进程**：创建、终止、调度、切换

本仓库在 `src/kernel/process.rs` 用 `Process` + `Scheduler` 搭建了一个最小框架。

## 进程需要哪些基本状态

从“能继续执行”的角度看，一个最小进程至少需要：

- **PID**：唯一标识
- **状态**：Ready/Running/Blocked/Terminated
- **栈**：函数调用与局部变量存放区域
- **PC/SP**：程序计数器与栈指针（恢复执行时必需）

本仓库的 `Process` 结构体包含：

- `pid`
- `state`
- `stack_pointer`
- `program_counter`
- `stack`（指向分配的栈内存）
- `stack_size`

其中 `stack` 来自第 06 章的内存分配器（`memory::allocate()`）。

## 进程状态机（简化版）

典型状态：

- Ready：可运行，等待 CPU
- Running：正在运行
- Blocked：等待事件（IO/锁/消息）
- Terminated：已结束

本仓库用 `ProcessState` 枚举表示这些状态，并在调度器中做最简单的状态变更。

## 创建/销毁：最小实现的意义

`Process::new()` 做了两件事：

1. 从内存分配器申请一块栈内存
2. 把 `stack_pointer` 初始化为栈顶（`stack + stack_size`）

销毁时 `destroy()` 调用 `memory::deallocate()`，但当前分配器不回收（占位），因此“销毁”主要是更新状态与清空指针，避免重复使用。

这类实现非常适合作为教学骨架：它让你先把“进程管理 API”跑通，为后续上下文切换与资源回收打下接口基础。

## 小结

本章你应该理解：

- 进程 = 代码 + 运行状态（最小集合：PID/状态/栈/PC/SP）
- 进程栈通常由内核分配与管理
- 学习型内核可以先实现“创建/列出/终止”的骨架，再逐步补齐真正的执行与隔离
