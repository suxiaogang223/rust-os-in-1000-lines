# 寄存器操作

## 概述

在裸机环境下，寄存器就是“最真实的状态”：函数调用约定、异常现场保存、系统调用参数传递、上下文切换……最终都会落回到寄存器的读写上。

本节会从三条主线理解寄存器：

1. **通用寄存器（x0~x31）**：保存计算状态、函数参数、返回值等
2. **调用约定（ABI）**：哪些寄存器需要保存？参数放哪？
3. **在 Rust 里如何访问**：`asm!`、以及为什么需要小心 `unsafe`

## RISC-V 通用寄存器速览

RISC-V 有 32 个通用寄存器（RV64 下每个 64 位）：

- `x0`：恒为 0（写入会被丢弃）
- `x1`：`ra` 返回地址
- `x2`：`sp` 栈指针
- `x10~x17`：`a0~a7` 参数/返回值寄存器（系统调用号通常放在 `a7`）
- `x5~x7, x28~x31`：`t0~t6` 临时寄存器（调用者保存）
- `x8~x9, x18~x27`：`s0~s11` 保存寄存器（被调用者保存）

更完整的对照表可以参考 `docs/02_riscv_basics.md`。

## 调用约定：为什么你需要关心

即使你不手写汇编，内核也会在以下场景直接依赖 ABI：

- **异常处理入口**：需要保存/恢复一部分寄存器，否则返回时现场会乱
- **系统调用**：用户态约定把参数放在 `a0~a5`，把系统调用号放在 `a7`
- **上下文切换**：切换“正在运行的进程”，本质是保存一组寄存器并恢复另一组

本仓库里你能看到两个最直接的例子：

- 在异常处理中读取系统调用号：`src/kernel/exception.rs` 使用 `asm!("mv {}, a7", ...)`
- 在系统调用封装中把参数“装进寄存器语义”：`src/kernel/syscall.rs` 用 `SyscallArgs` 表示 `a0~a7`

## 在 Rust 里访问寄存器（asm!）

Rust 的 `core::arch::asm!` 允许在 `no_std` 环境下使用内联汇编，但它是 `unsafe` 的。

示例：读取 `a7`（系统调用号）：

```rust
let syscall_num: usize;
unsafe {
    core::arch::asm!("mv {}, a7", out(reg) syscall_num);
}
```

示例：把值写入某个寄存器（概念演示）：

```rust
let value: usize = 42;
unsafe {
    core::arch::asm!("mv a0, {}", in(reg) value);
}
```

### 使用 `asm!` 的注意事项

- **编译器可能重排/优化**：需要时使用 `options(nomem, nostack, preserves_flags)` 等选项（按需）
- **寄存器分配**：`out(reg)` 让编译器选择一个通用寄存器接收输出
- **`unsafe` 的边界要小**：把汇编封装成小函数（本仓库在 `src/arch/riscv.rs` 对 CSR 做了封装）

## 和后续章节的衔接

- 异常/中断：需要理解 `mepc/mcause/mtval` 等 CSR，并在异常入口保存寄存器现场
- 进程/调度：需要明确哪些寄存器在切换时必须保存（通常是所有通用寄存器 + 关键 CSR）
- 系统调用：需要掌握 `a0~a7` 的参数约定
