# 用户接口

## 概述

“用户接口”指的是：用户态程序如何以更友好的方式调用系统调用，而不是到处写内联汇编和寄存器搬运。

在真实系统里，用户接口通常表现为：

- C 标准库的 `write()/exit()/fork()` 等函数
- Rust 的 `std`/`libc`/`nix` 等封装

在教学 OS 中，我们通常会提供一个很小的用户态运行时（userland runtime），里面包含：

- syscall wrappers：把函数调用转成 `ecall` + 寄存器约定
- 基础输出：`print!/println!` 之类
- 简单的启动入口（用户态 `_start`）

本仓库目前主要在内核侧演示 syscall 分发，用户侧的“完善封装”仍属于后续扩展方向。本节给出推荐的接口形态与落地思路。

## 推荐的用户态封装形态（示例）

以 `write` 为例，用户态希望这样用：

```rust
user::write(1, b"hello\n");
```

封装内部负责：

1. 把 `SYS_WRITE` 放到 `a7`
2. 把 `(fd, buf_ptr, len)` 放到 `a0/a1/a2`
3. 执行 `ecall`
4. 取回 `a0` 作为返回值

## 与本仓库现有代码的关系

`src/kernel/syscall.rs` 里已经有了 `sys_write/sys_exit/sys_getpid` 这类“函数式封装”，但它们目前仍处于内核 crate 内部，更多是为了演示 syscall 参数结构与分发路径。

当你要真正做用户态程序时，建议把这类封装迁移到：

- `src/user/` 下的一个用户态库模块（或单独的用户态 crate）

并让用户程序只依赖该库，而不直接引用内核模块。

## 小结

本章你应该理解：

- 用户接口的目的：把寄存器/`ecall` 细节封装起来
- 真实系统会提供 libc/运行时；教学 OS 可以先写最小 wrappers
- 本项目当前以内核侧机制为主，用户态封装可作为自然的下一步扩展
