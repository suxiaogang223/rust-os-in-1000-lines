# 内存保护

## 概述

内存保护的目标是：**防止一个错误（尤其是用户态错误）破坏整个系统**。

它通常依赖两类机制：

1. **特权级**：用户态/内核态权限隔离（第 09 章）
2. **地址空间与权限**：分页/页表把不同地址映射到不同权限（第 08 章）

本节先说明“我们想要什么”，再结合本项目目前的实现说明“现在做到了哪一步”。

## 我们希望保护什么

理想情况下：

- 用户态不能读写内核内存
- 用户态不能访问 MMIO 设备寄存器
- 不同进程之间的地址空间互相隔离
- 内核内部的关键区域（如只读代码段）也可设置为不可写

## 常见实现手段（RISC-V）

### 1) 页表权限位（PTE flags）

在分页模式下，每个页表项（PTE）会包含：

- Valid / Read / Write / Execute
- User 可访问位（U）
- 以及 Accessed/Dirty 等状态位

本仓库在 `src/kernel/paging.rs` 定义了一组 PTE 标志位（`PTE_R/PTE_W/PTE_X/PTE_U` 等），用于演示权限概念。

### 2) PMP（Physical Memory Protection）

即使不启用分页，RISC-V 也可以用 PMP 在物理地址层面做一定的访问控制。

本教程暂不展开，但当你需要在机器模式下进一步限制访问时，PMP 是一条可走的路线。

## 本项目当前的状态

目前本仓库的重点是把“机制框架”搭起来：

- 有最小内存分配器（第 06 章）
- 有分页管理的演示代码（第 08 章）
- 有用户态切换的演示代码（第 09 章）

但要达到“真正的隔离”，还需要补齐：

- 真实的页表结构（例如 Sv39 三层页表）
- `satp` 设置与 TLB 刷新（SFENCE.VMA）
- trap 返回路径与上下文切换

你可以把它理解成：目前更多是在“讲清楚 OS 需要哪些积木”，并给出最小可运行的形态。

## 小结

本章你应该理解：

- 内存保护依赖特权级 + 地址空间权限
- 页表权限位是最常见的隔离手段之一
- 本项目当前以演示框架为主，后续可以逐步增强到真正的进程隔离
